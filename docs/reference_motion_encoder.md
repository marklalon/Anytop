# 参考动作编码器：免 retarget 的跨物种动作迁移

> 状态：设计稿，未实现。
> 现状见 [anytop_model_architecture.md](anytop_model_architecture.md) §9：参考动作不进入 decoder，跨骨架时只能先 retarget
> 到目标骨架，再走 img2img / inpainting。本文提出一条与它并存的新路径。

---

## 0. 目标与边界

**目标**：给一段**任意物种**的参考动作，加上一副目标骨架，生成「目标骨架在做参考里的动作」。
不经过 retarget，也不需要关节对应表。例子：人走路的参考 + 四足骨架 → 四足用后腿站起来走。

**同时保持**：
- 现有的纯文本生成（action_label + species_tags）不退化；
- 支持「文字 + 参考」组合生成。

**硬性规则**：
- **合成数据永不作为生成目标。** 所有训练目标都是真实 clip。retarget 之类的合成产物最多只出现在编码器输入侧（§4.2）。
- joint_parts / joint_contact 不进入这条路径。

**不追求**：参考的逐关节姿态复现。跨物种时能迁移的是运动内容（§1），不是关节角。

---

## 1. 理论基础：视频模型为什么不需要配对数据

视频模型做「人跳舞 → 猫跳舞」，靠的是三件事：

1. **自监督重建**：从同一段视频里分出运动信号 M 和外观 A，再用 (M, A) 重建原视频。推理时把 M 和 A 换成来自不同视频的。全程不需要配对数据。
2. **M 有信息瓶颈**：M 装不下外观，模型只能从 A 和先验里生成外观。
3. **组合泛化**：「直立挥臂的身体布局」和「猫的局部外观」是分别学会的，推理时组合。训练集里不需要有「猫跳舞」。

映射到 AnyTop：

| 视频模型 | AnyTop | 来源 |
|---|---|---|
| 外观 A | 骨架身份：拓扑、骨长比例、关节名、rest pose、structural channel | 目标骨架的现有条件，不改 |
| 运动 M | 运动内容：根轨迹、躯干朝向与直立程度、几条肢体在支撑、落脚相位、节奏、发力时序 | **新增的 z** |
| 文本 | action_label / species_tags | 现有条件，可选 |

**z 剥离的是「骨架身份」，不是「运动风格」。** 「直立、两肢交替支撑」属于运动内容，正是这里要迁移的东西，z 必须保留它。

---

## 2. 为什么 z 不会携带骨架身份

这是整个方案成立的关键论证。

自重建训练里，**解码器本来就拿到了同一副骨架**的全部条件。骨架身份对解码器来说是已知信息，z 再编码一遍不会降低任何重建误差。只要 z 有瓶颈，优化就没有动力把有限的容量花在骨架身份上，容量会优先给解码器从骨架推不出来的东西，也就是这一段的运动。

这个论证在两种情况下会失效：

- **瓶颈太宽**：z 有余量时，顺手把逐关节的姿态也编进去。解码器学会直接抄 z，同物种重建很好，跨物种时 z 是另一副骨架的姿态码，解码器读不懂。
- **编码器输入和解码器骨架总是完全相同**：z 可以用「这副骨架专属的坐标」来表达运动，不必学一种骨架无关的表达。

§3.1 的瓶颈和 §4.1 的结构增强，分别针对这两种失效。§6 的泄漏探针负责测量它们是否起作用。

## 3. 模型改动

### 3.1 运动编码器 E（新模块 `model/motion_encoder.py`）

**结构**：
- 输入：参考 clip 的干净特征 x0 `[J_s, F, T]`，以及参考骨架自己的 rest token、关节名 embedding、structural channel。复用 InputProcess 的同类投影，权重独立。
- 少量层 spatial + temporal attention，复用 `GraphMotionDecoder` 的层实现，宽度小于主干。
- 每帧用 K 个 learned query 对全部有效关节做 cross-attention 池化，输出 `z [T, K, d_z]`。

**理由**：
- **K 个 query 池化**让 z 的形状与关节数无关，任何源骨架都映射到同一个空间。cross-limb block 已经用这个结构表达「全身节奏」，被验证过可用。
- **为什么输出逐帧 z**：参考和输出处在同一个时间窗口里，帧对齐是恒等映射。逐帧 z 让模型不必学习时间对齐。时间上下文由编码器的 temporal attention 写进每一帧。
- **为什么不需要关节顺序增强**：模型里没有关节 index 位置编码（关节身份只来自名字、几何和成对关系），所以「attention + query 池化」天然对关节排列不变。

**瓶颈**：K·d_z 要远小于每帧的 J·F。这是 §2 论证的前提，作为首要的扫描超参。起点建议 K=8、d_z=32，再往小扫。

### 3.2 解码器注入：每层一个逐帧 cross-attention 子层

在每个 decoder layer 的 spatial attention 之后，插入 `ref cross-attn`：第 t 帧的每个关节 token 作为 query，读取 z[t] 的 K 个槽。输出经过零初始化的标量 gate 后加入残差。

**理由**：
- **软对应**：关节自己决定读哪个槽。目标骨架的后腿去读「支撑肢」那个槽，前腿读「上肢」那个槽，这就是可学习的软对应，取代 retarget 的硬映射。query 带着目标关节的名字和几何，所以对应的依据是语义和结构。
- **为什么放在 spatial 之后**：同一帧内先完成关节间通信，再读参考，之后的 temporal attention 负责把读到的内容沿时间整合。
- **零初始化 gate**：训练起点与现有模型完全等价。gate 的大小可以直接衡量模型有没有在用 z。
- **为什么不复用 cross-limb block**：cross-limb 只在后几层启用，语义是「目标肢体之间交换节奏」。把 z 混进去，两者的作用就无法分开测量，也无法单独关闭。

### 3.3 Null 语义：硬旁路

`ref_active=False` 时，ref cross-attn 子层整个跳过：输出置零，不使用 learned null token。

**理由**：没有参考时，计算图与现有模型逐项相同，纯文本模式最大程度不受影响。这与 species FiLM 的 hard-null bypass 是同一个思路。

**工程约束**：`ref_feats` / `ref_mask` / `ref_active` 每个 batch 都存在。没有参考时用全 False，不传 None，保持 cond key 集合稳定（compile 契约）。

## 4. 训练

### 4.1 目标与 dropout

- **编码器输入**：同一个 clip，干净的 x0（经过 §4.2 的增强）。**解码器目标**：同一个 clip 的原始版本。
- 新增 `--ref_cfg_drop_prob`，对 ref 做硬丢弃，建议 0.3–0.5。与现有的 `--action_label_cfg_drop_prob` 和 `--species_cfg_drop_prob` 各自独立抽签。

**理由**：
- 独立 dropout 让「只有参考」「参考 + 文字」「只有文字」「无条件」四种组合都成为训练过的模式，推理时任选。
- ref drop 不能太低。z 携带的信息远比 label 丰富，有 z 时 label 通路几乎拿不到梯度。label 通路要靠 z 缺席的样本继续学习，纯文本质量取决于此。

### 4.2 编码器侧增强（只作用于编码器输入，目标永不改变）

| 增强 | 现有实现 | 打破的是什么 |
|---|---|---|
| leaf-drop | `truebones_utils/leaf_drop.py` | 拓扑末端：z 不能依赖精确的关节数和链长 |
| 骨长比例 | `truebones_utils/bone_length_aug.py` | 身体比例：z 不能依赖源的骨长 |
| 整关节名置空 | 与 `joint_name_drop_prob` 同一机制 | 名字：z 不能只靠名字识别部位，必须结合几何和运动 |

**理由**：每种增强都是「同一段运动，换一副骨架形态」，而目标不变。这就要求 z 对这些形态变化保持不变（§2 的第二个失效点）。三种增强都不改变运动本身，所以不会损害 z 应该携带的内容。

**实现要点**：loader 为编码器单独生成一份增强副本（独立的 cond 切片），解码器侧的 cond 和目标不受影响。leaf-drop 只删不增，副本的关节数不超过原骨架，可以落在同一个 joint bucket 里。

**不做时间增强**：编码器输入与目标必须逐帧对齐（§3.1）。

### 4.3 条件阶段：retarget 作为编码器输入

**启用条件**：§6 的评测显示，同 body plan 的迁移可用，但跨 body plan 时解码器不听 z。

**做法**：离线把真实 clip（物种 A）retarget 到随机的物种 B，作为**编码器输入**。解码器骨架和目标仍是 A 的原始 clip。

**理由**：§4.2 的增强都不改变 body plan，这是唯一能让编码器看到「同一段运动在完全不同身体上」的信号。retarget 的瑕疵只出现在输入侧，不违反硬性规则；它的作用是让编码器学会从有缺陷的跨骨架表达里读出运动。

**过滤**：只剔除明显失败的样本（倒地、翻转之类）。原因是这类样本会让编码器学到「参考不可信」，反而降低 z 的影响力。

### 4.4 参数与版本

- 新增参数集中在编码器和每层的 ref cross-attn，体量远小于主干。
- state_dict 新增键，CKPT 版本 +1。
- 从头训练，不 warm start。

## 5. 推理

### 5.1 输入
- 参考：在**它自己的骨架上**转成特征，不 retarget。
  - npy 来源：现成可用；
  - 原始文件：走新骨架预处理生成 cond 和特征。
- 帧长：沿用现有 reference 的「重采样到窗口」规则。

### 5.2 新参数
- `--reference_mode {retarget, encode}`：默认 `retarget`，即现有行为不变。
- `--ref_cfg_scale`。

### 5.3 CFG（组合式，x0 上的代数与现有实现相同）

```
out = x0(∅, ∅)
    + s_ref · (x0(ref, ∅)   − x0(∅, ∅))
    + s_txt · (x0(ref, txt) − x0(ref, ∅))
```

- 不给 label 时：去掉第三项，两次前向。
- 给 label 时：三次前向，顺序执行。
- 实现为一个新 wrapper，不与现有 action / species wrapper 嵌套，避免前向次数相乘。

### 5.4 推荐默认（干净迁移）
- action_label 不给；
- species FiLM 置 null（`species_active=False`，训练里由 `species_cfg_drop_prob` 覆盖到）。

**理由**：目标物种自己的 descriptor 会把动作拉回它的典型步态，正好与「让四足站起来」相冲突。置 null 之后，运动由 z 决定，骨架条件只负责「外观」。

per-joint species FiLM 始终开启。它绑定在关节名上，属于骨架条件的一部分。

## 6. 评测与验收

| 项 | 方法 | 回答的问题 |
|---|---|---|
| 纯文本不退化 | ref-null 模式下，与基线比较 MotionQualityScorer 和 val l_simple | §3.3 的硬旁路是否真的隔离了影响 |
| 同物种重建 | val clip 自编码自重建，误差对比 ref-null | z 是否携带了运动 |
| 泄漏探针 | 冻结 E，用线性探针从时间池化后的 z 预测源物种 ID / 骨长比例；**只用作诊断，不作为损失** | §2 的论证是否成立。探针准确率高，就收紧瓶颈或加强 §4.2 |
| z 是否被使用 | 每层 ref gate 的大小；同一目标、换不同参考时输出是否相应变化 | 解码器有没有走「无视 z」的捷径 |
| 跨物种迁移 | 固定一组评测对（双足→四足、四足→不同体型的四足、飞行→飞行）。比较源与输出之间骨架无关的量：按 L 归一化的根速度曲线、躯干俯仰（直立程度）、全身运动能量随时间的曲线。同时用 scorer 打合理性分，并人工看 | 迁移了多少运动内容，结果是否合理 |

跨物种没有 GT，所以只比较骨架无关的量，不比较关节角。

## 7. 前置检查：数据决定上限

自重建训练中，z 和骨架永远一致。解码器只有在**同一骨架上见过不同姿态和支撑方式**时，才会学到「姿态由 z 决定，而不是由骨架决定」。否则它会只从 z 读节奏，姿态仍按骨架先验生成。

**动手前先统计**：有多少物种在数据里拥有 ≥2 种姿态或支撑方式。例如四足的站、坐、趴、立起，双足的走、爬、趴，鸟的走和飞。

- 这个数量决定了「四足站起来走」这类跨 body plan 迁移的上限，也决定了 §4.3 是否需要启用。
- 拟人化动物的 rig（动物关节名 + 直立步态）是最有价值的桥接样本，要单独列出来。

## 8. 明确不做

| 不做 | 原因 |
|---|---|
| 对 species_tags 做对抗约束 | tags 描述的 body plan 和步态属于运动内容，剥掉它们就剥掉了要迁移的东西 |
| 把 z 拆成两层 | 只是对上面那个错误的补救。去身份的目标定对之后，一层就够了 |
| 合成数据作为目标 | 扩散模型会把 retarget 的瑕疵当作合理分布学进去（硬性规则） |
| 按 joint_parts 路由 z | joint_parts 不在扩散路径里；对应关系由 ref cross-attn 学出来 |
| 每帧 z 带额外的时间 PE 或对齐模块 | 窗口内帧对齐是恒等映射（§3.1） |
| 编码器侧做关节顺序增强 | 编码器结构上对关节排列不变（§3.1） |
| 删除现有的 retarget + img2img | 两者正交，物种相近时仍然可用；`--reference_mode` 默认保持现状 |
